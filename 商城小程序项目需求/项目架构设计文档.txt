========================================
商城小程序项目技术架构设计文档
========================================

一、项目概述
----------------------------------------
本项目是一个完整的商城小程序系统，包含三个子项目：
1. 商城小程序前端（微信小程序）
2. 商城小程序后台管理系统（全栈一体化）
3. 后端API服务（为小程序提供接口）

这三个项目协同工作，共同构成一个完整的电商系统。

三、三个子项目详细介绍
----------------------------------------

【项目一：商城小程序前端】
---------------------
1. 技术栈
   - 微信小程序原生开发（不使用第三方框架）
   - 小程序云开发（可选，用于存储和简单函数）
   - 微信小程序API（用户授权、支付等）

2. 核心功能
   - 用户浏览商品（首页、分类、商品详情）
   - 购物车管理
   - 订单管理
   - 用户个人信息管理
   - 收货地址管理

3. 数据流向
   小程序 → 调用后端API → 获取数据 → 展示给用户

4. 部署方式
   - 上传代码到微信开发者平台
   - 微信审核通过后发布


【项目二：后端API服务】
---------------------
1. 技术栈
   - Node.js + Express框架
   - MySQL或MongoDB数据库
   - JWT令牌认证（用于用户登录验证）

2. 核心职责
   - 接收小程序发来的请求
   - 处理业务逻辑（如：添加商品到购物车、创建订单）
   - 与数据库交互（查询、保存数据）
   - 返回数据给小程序

3. 主要接口
   - 商品相关：获取商品列表、商品详情
   - 购物车相关：添加、删除、更新购物车
   - 订单相关：创建订单、查询订单
   - 用户相关：登录、获取用户信息
   - 地址相关：管理收货地址

4. 部署方式
   - 部署到服务器（如：腾讯云、阿里云）
   - 配置域名和HTTPS证书


【项目三：管理后台】
---------------------
1. 技术栈
   - 前端：Vue.js + Element UI（界面组件库）
   - 后端：Node.js + Express（与API服务在同一项目）
   - 数据库：与API服务共用同一数据库

2. 核心功能
   - 商品管理（增删改查）
   - 订单管理（查看、发货、取消）
   - 用户管理
   - 数据统计（订单数、销售额等）

3. 数据流向
   管理员操作 → 管理后台 → 直接连接数据库或调用API → 更新数据

4. 部署方式
   - 前端打包后部署到静态服务器
   - 后端部署到服务器
   - 管理员通过浏览器访问


四、技术选型说明
----------------------------------------

【为什么选择这些技术？】

1. 微信小程序原生开发
   - 官方支持，性能好
   - 无需学习额外框架
   - 直接使用微信生态（登录、支付）

2. Node.js + Express
   - JavaScript语言，前后端统一
   - Express框架简单易用
   - 开发速度快

3. Vue.js + Element UI
   - 组件丰富，开发效率高
   - 界面美观，用户体验好
   - 学习成本低

4. MySQL或MongoDB
   - MySQL：适合结构化数据（订单、用户）
   - MongoDB：适合灵活的数据结构（商品详情）
   - 根据实际需求选择，初期可以只用MySQL


五、安全性设计
----------------------------------------

【常见网络攻击防护措施】

1. SQL注入攻击防护
   问题：黑客通过输入恶意SQL代码来攻击数据库
   防护：
   - 使用参数化查询（Prepared Statements）
   - 对所有用户输入进行验证和过滤
   - 禁止拼接SQL语句

2. XSS跨站脚本攻击防护
   问题：黑客在网页中插入恶意脚本
   防护：
   - 对用户输入进行HTML转义
   - 使用CSP（内容安全策略）
   - 小程序本身有严格的代码隔离

3. CSRF跨站请求伪造防护
   问题：黑客利用用户已登录状态进行非法操作
   防护：
   - 使用CSRF Token（令牌）
   - 验证请求来源
   - 重要操作需要二次确认

4. 用户认证安全
   问题：未授权用户访问系统
   防护：
   - 使用JWT令牌（有有效期）
   - 密码加密存储（使用bcrypt等加密算法）
   - 微信小程序使用官方登录接口

5. 接口安全
   问题：接口被恶意调用
   防护：
   - 使用HTTPS加密传输
   - API接口添加签名验证
   - 限制接口调用频率（防止刷接口）
   - 管理员接口需要权限验证

6. 数据安全
   问题：敏感数据泄露
   防护：
   - 用户密码、手机号等敏感信息加密存储
   - 数据库访问权限控制
   - 定期备份数据
   - 不在日志中记录敏感信息

7. 小程序安全
   问题：小程序代码被破解
   防护：
   - 小程序代码经过微信加密
   - 敏感逻辑放在后端API
   - 不在小程序中存储敏感信息

8. 文件上传安全
   问题：上传恶意文件
   防护：
   - 限制文件类型和大小
   - 文件重命名（避免覆盖）
   - 扫描上传的文件（病毒检测）
   - 存储路径不暴露

9. 支付安全
   问题：支付流程被篡改
   防护：
   - 使用微信官方支付接口
   - 支付金额、订单号等关键信息在后端验证
   - 支付成功后通过回调确认

10. 日志和监控
    问题：无法追踪安全问题
    防护：
    - 记录关键操作日志
    - 监控异常访问
    - 设置告警机制


六、数据流转说明
----------------------------------------

【典型业务流程：用户购买商品】

1. 用户在小程序中浏览商品
   小程序 → 调用 /api/goods/list → 后端API → 查询数据库 → 返回商品列表

2. 用户点击商品查看详情
   小程序 → 调用 /api/goods/detail → 后端API → 查询数据库 → 返回商品详情

3. 用户加入购物车
   小程序 → 调用 /api/cart/add → 后端API → 验证用户登录 → 保存到数据库 → 返回成功

4. 用户点击结算
   小程序 → 调用 /api/order/confirm → 后端API → 查询购物车和地址 → 返回订单确认信息

5. 用户提交订单
   小程序 → 调用 /api/order/create → 后端API → 创建订单 → 扣减库存 → 清空购物车 → 返回订单号

6. 用户支付
   小程序 → 调用微信支付 → 后端验证支付结果 → 更新订单状态 → 通知用户

【管理员操作流程：添加商品】

1. 管理员登录后台
   管理后台 → 调用 /admin/auth/login → 验证账号密码 → 返回管理员令牌

2. 管理员添加商品
   管理后台 → 调用 /admin/goods/save → 后端API → 验证管理员权限 → 保存商品到数据库 → 返回成功

3. 商品自动显示在小程序
   小程序首页 → 调用 /api/goods/recommend → 后端API → 查询推荐商品 → 返回给小程序展示


七、数据库设计概览
----------------------------------------

【主要数据表】

1. 商品表（goods）
   - 商品名称、价格、库存、分类、图片等

2. 分类表（category）
   - 分类名称、图片、排序等

3. 用户表（user）
   - 微信openid、昵称、头像等

4. 订单表（order）
   - 订单号、用户ID、金额、状态、时间等

5. 订单商品表（order_item）
   - 订单ID、商品ID、数量、价格等

6. 购物车表（cart）
   - 用户ID、商品ID、数量等

7. 收货地址表（address）
   - 用户ID、收货人、电话、地址等

8. 轮播图表（banner）
   - 图片、链接、排序、状态等

9. 管理员表（admin）
   - 账号、密码（加密）、权限等


八、接口设计原则
----------------------------------------

1. RESTful风格
   - GET：获取数据
   - POST：创建数据
   - PUT：更新数据
   - DELETE：删除数据

2. 统一返回格式
   {
     "code": 200,        // 状态码：200成功，其他失败
     "message": "成功",  // 提示信息
     "data": {}          // 返回数据
   }

3. 统一错误处理
   - 400：请求参数错误
   - 401：未登录
   - 403：权限不足
   - 404：资源不存在
   - 500：服务器错误

4. 分页处理
   - 列表接口支持分页
   - 默认每页10条，可自定义


九、开发建议
----------------------------------------

1. 开发顺序
   第一步：搭建后端API基础框架
   第二步：开发小程序前端页面
   第三步：开发管理后台
   第四步：联调测试

2. 开发工具
   - 代码编辑器：VS Code
   - 数据库管理：Navicat或phpMyAdmin
   - API测试：Postman
   - 版本控制：Git

3. 测试建议
   - 单元测试：测试每个函数
   - 接口测试：测试每个API接口
   - 功能测试：测试完整业务流程
   - 安全测试：测试安全性措施

4. 代码规范
   - 统一代码风格
   - 添加代码注释
   - 函数命名清晰
   - 遵循最佳实践

【生产部署步骤】

1. 服务器准备  
   - 购买云服务器（如：腾讯云、阿里云）  
   - 安装 Node.js 运行环境  
   - 安装 MySQL 数据库  
   - 安装 Nginx 或其他静态资源服务器（可选）

2. 后端部署  
   - 上传后端代码到服务器  
   - 安装依赖（npm install）  
   - 配置环境变量（数据库地址、密钥等）  
   - 启动服务（使用 PM2 等进程管理工具）

3. 管理后台部署  
   - 管理后台前端代码打包（npm run build）  
   - 上传打包后的静态文件到静态资源服务器（如 Nginx html 目录）  
   - 后端部署方式同上

4. 小程序部署  
   - 在微信开发者工具上传代码  
   - 配置生产服务器 API 域名（需在微信小程序后台设置为合法域名）  
   - 提交审核并发布

5. 域名与 HTTPS  
   - 申请并解析域名  
   - 申请 SSL 证书（如 Let's Encrypt 免费证书）  
   - 配置 Nginx 反向代理、HTTPS

- 数据库可本地部署 MySQL，也可以通过 Docker 快速一键启动数据库服务

【本地开发部署步骤】

1. 本地环境准备  
   - 安装 Node.js、npm  
   - 安装 MySQL（推荐使用 Docker 本地启动数据库）  
   - 安装前端开发工具（如 VS Code）

2. 后端启动  
   - 拉取项目代码至本地  
   - 安装依赖（npm install）  
   - 配置本地环境变量（.env.development），如本地数据库地址等  
   - 启动开发服务（npm run dev 或 nodemon）

3. 管理后台前端开发  
   - 安装依赖（npm install）  
   - 启动前端开发服务（npm run dev），支持热更新  
   - 前端通过配置代理访问本地后端 API

4. 小程序开发  
   - 微信开发者工具设置本地 API 域名和端口为 request 合法域名  
   - 可通过代理或本地局域网调试 API

5. 提示  
   - 本地环境推荐使用统一端口和环境变量管理，避免与线上端口冲突
   - 建议使用 Docker Compose 管理多个开发依赖服务
   - 如需本地 HTTPS，可自签证书（非必需）

十二、总结
----------------------------------------

本项目采用简洁的技术架构，适合中小型商城项目：
- 小程序前端：微信原生开发，用户体验好
- 后端API：Node.js + Express，开发效率高
- 管理后台：Vue + Element UI，界面美观
- 数据库：MySQL，稳定可靠

安全性方面，采用了多层防护措施，能够有效防范常见的网络攻击。

整个架构设计简洁明了，易于理解和维护，适合快速开发和迭代。
